1.1 前端基础概念：网页三要素、开发框架与构建工具#

用户在浏览器中输入网址打开一个 Web 应用时，程序按运行位置分为两部分：下载到用户浏览器中运行、负责展示界面并响应点击输入的程序称为前端（Frontend）；部署在远程服务器上运行、负责处理业务逻辑与存取数据的程序称为后端（Backend）。要理解现代前端技术栈里众多工具的关系，首先需要分清“浏览器原生能直接运行什么”与“开发者写代码时使用什么”。

无论一个网站的界面多复杂，浏览器底层原生能直接解析和执行的只有三种基础语言：

第一种是 HTML（HyperText Markup Language，超文本标记语言），它是用于标注网页内容结构的标记语言，用来声明页面上有一行标题、一个文本输入框、一张数据表或一个提交按钮。浏览器读取 HTML 文本后，会在内存中把这些标签解析成一棵树状的元素结构，称为 DOM（Document Object Model，文档对象模型），并据此把画面绘制在屏幕上。第二种是 CSS（Cascading Style Sheets，层叠样式表），它是描述网页视觉外观的样式语言，用来规定每个元素的字号、颜色、内外边距以及行列排版。第三种是JavaScript（简称 JS），它是运行在浏览器内的脚本编程语言。开发者用 JavaScript 编写事件处理程序；当用户点击按钮时，浏览器执行这段脚本去读取输入框文字、向后端服务器发送网络请求，或调用浏览器提供的接口增删、修改内存里的 DOM 节点，使网页不必整页刷新就能局部变换内容。

只写少量简单页面时，开发者可以直接手写 HTML、CSS 和原生 JavaScript 文件。但当团队协作开发包含几十个复杂交互页面的企业级前端时，直接手写这三种基础文件会遇到三处工程瓶颈，由此引出了现代前端常用的四项开发工具：

第一处瓶颈是界面状态同步困难。在包含任务列表、顶部数量统计、右侧详情抽屉和操作按钮的复杂页面中，同一条任务的状态同时影响多处画面。如果开发者用原生 JavaScript 手工编写“找到某节点并修改文字”的命令式代码，一旦漏改某一处，界面就会出现列表显示“已完成”、右侧详情仍显示“运行中”的自相矛盾。为此工程上引入了 React。React 是用于构建用户界面的前端组件库：开发者把页面拆分成导航栏、任务表格、详情面板等独立的组件（Component），并使用 JSX 语法（一种在 JavaScript 函数中书写类似 HTML 标签的语法）声明“给定某份数据时，这个组件应当呈现什么结构”。用 React 编写的界面最终在浏览器里展示时仍然是标准的 HTML 元素：当底层数据变化时，React 的运行库会在浏览器内存中自动比对新旧结构差异，代替人工去调用浏览器接口创建或更新对应的 HTML DOM 节点（对于需要让搜索引擎直接抓取完整正文的公开网页，也可以先在服务器上把 React 组件直接渲染成 HTML 字符串发给浏览器）。

第二处瓶颈是多人协作的样式命名冲突。多人共同维护全局 CSS 文件时，修改某个样式类名很容易意外破坏其他页面的排版。Tailwind CSS 是一套原子化 CSS 样式工具库，它预先定义好 px-4 （左右内边距）、bg-slate-800 （深色背景）等细粒度工具类名；开发者直接把这些类名写在 React 组件标签的属性上，样式改动就只影响当前组件。第三处瓶颈是复杂数据的拼写与类型错误。原生 JavaScript 在代码运行前不检查对象字段，开发者把属性名 userName 误写成 username 时编辑器不会报警，只有等用户点开对应界面才会报错。TypeScript（简称 TS）是在 JavaScript 基础上增加了静态类型系统的编程语言：开发者先声明数据结构包含哪些字段及各自的类型，编码时一旦写错字段名或传错类型，编辑器和编译器就会直接标红报错。

引入 React、Tailwind CSS 和 TypeScript 提高了开发与维护效率，但浏览器本身并不认识 .tsx 组件语法和 TypeScript 类型标注。这就需要第四项工具：Vite。Vite 是前端构建与打包工具，负责把开发者编写的工程源码翻译成浏览器认识的 HTML、CSS 与 JavaScript。图 1.1 串联了从开发源码到浏览器最终画面的完整转换链条。

顺着图 1.1 从左向右看：本地写代码时，Vite 每次只即时转换刚保存的单个文件并通知浏览器局部刷新（称为热更新）；准备部署上线前，Vite 将全套源码打包成标准的 index.html 、.css 和 .js 文件，并在文件名中附上由文件内容算出的哈希指纹（如 app.8f3a2c.js ）。内容未变时浏览器直接读取本地缓存，代码发版更新后哈希改变，浏览器便自动下载新文件。

1.2 后端基础概念：运行环境、服务端框架、数据库与反向代理#

图 1.1 生成的前端文件下载到用户个人设备上运行，存在两项天然边界：一是任何用户按下 F12 键打开浏览器开发者工具，都能看到前端代码与收到的接口报文，因此数据库密码、第三方大模型密钥和权限判断规则绝不能放在前端；二是浏览器关闭或更换设备后，仅存在前端内存里的数据就会消失。凡是需要跨设备持久保存的数据、核心业务规则和外部模型调用，都必须放在受控服务器的后端（Backend）中完成。构建后端服务涉及四组基础组件：

第一组是服务端运行环境与路由框架。JavaScript 最初只能在浏览器内部运行；Node.js 是安装在服务器操作系统上的 JavaScript/TypeScript 运行环境，使开发者能够用同一种语言编写服务器端程序，并在等待数据库或外部大模型网络返回的空隙里继续接待其他用户的并发连接。运行在 Node.js 之上的 Express 是服务端 Web 框架，负责监听网络请求并按路径和方法分发给对应的处理函数（例如将读取项目列表的 GET /api/projects 请求分发给项目查询函数）。由于前后端都用 TypeScript 编写，两边可以直接共用同一套数据结构定义。

第二组是关系型数据库与对象关系映射。关系型数据库（Relational Database，如 MySQL 8.4）是按结构化二维表格持久化存储业务记录（如用户表、项目表、任务表）的软件系统。它的核心保障机制是事务（Transaction）：开发者可以把“扣减账户剩余额度”和“插入一条新任务记录”放进同一个事务中执行，数据库保证这两步要么全部成功生效，要么中途出错时全部回滚撤销，不会留下扣了额度却没生成任务的残缺数据。为了避免在业务代码里到处拼接容易写错列名的 SQL 查询字符串，后端通常配合 ORM（Object-Relational Mapping ，对象关系映射，如 Drizzle ORM ）库访问数据库：开发者先用TypeScript 代码定义每张表的列名与类型，后续编写查询语句时就能获得自动补全与编译期类型检查。

第三组是文件对象存储。关系型数据库适合存放结构化的行列记录，却不适合直接把几十兆的 PDF 文档或压缩包塞进表格字段里。大体积二进制文件通常交由专门的对象存储（Object Storage）系统按“存储桶（Bucket）+ 对象路径（Key）”保管，MySQL 数据库中只记录文件的编号、归属者、字节大小与存储路径。

第四组是域名解析与边缘反向代理。生产服务器内部的 Node.js 程序和数据库通常只监听内网端口，不直接向公网裸露。用户在浏览器输入域名后，先由 DNS（Domain Name System，域名系统）将域名解析为服务器的公网 IP 地址；加密的 HTTPS 请求到达服务器后，由最外层的反向代理（Reverse Proxy，常用Nginx 或 OpenResty）统一接待。反向代理是位于公网与内部后端服务之间的网关软件，承担两项职责：一是集中管理 HTTPS 数字证书（常搭配免费证书机构 Let's Encrypt 与自动续期工具 acme.sh ），完成加密流量解密后再把明文请求转给内网的 Express 进程；二是按访问域名或路径将流量分流到不同的内部服务。

1.3 全栈架构串联：公开展示站点与核心业务系统的协同#

把 1.1 节的前端技术与 1.2 节的后端组件组合起来，就能搭起一套完整的企业级应用。在实际产品中，访问系统的用户分为两类：一类是尚未注册的外部访客与搜索引擎爬虫，主要浏览产品功能介绍、技术文档或体验轻量演示；另一类是已登录的企业员工，每天在系统内管理团队项目、上传业务资料并运行内嵌的 AI 分析任务。如果把两类页面打包进同一个前端工程并共用同一个后端进程，外部访客只看一页产品介绍也得连带下载体积庞大的业务交互脚本，拖慢首屏速度；同时业务后端为了给公开页面放行免登录访问，权限校验规则也容易混入漏洞。

因此，企业级全栈系统通常按访问性质拆分为公开展示站点与核心业务系统两套前后端应用，由入口反向代理统一分流，整体拓扑如图 1.2 所示。

结合图 1.2 可以看清前两节概念在两套应用中的具体用法。上半部的公开展示站点追求首屏打开速度与检索可见性：其服务端把 1.1 节的组件直接输出为含完整正文的 HTML，并附带 SEO（Search Engine Optimization，搜索引擎优化）元标签、站点地图 sitemap.xml 、抓取规则 robots.txt 以及供搜索引擎和 AI 检索系统识别页面语义的 JSON-LD 结构化数据；公开访问量统计接入独立运行的分析服务（如基于PostgreSQL 的 Umami），避免海量匿名访问挤占主业务数据库。下半部的核心业务系统服务已登录团队：前端搭配客户端路由库（如 Wouter）切换页面，并用请求缓存库（如 TanStack Query）按“账号 + 企业空间 + 资源编号”管理前端缓存，自动丢弃快速切换任务时晚到的过期响应，在退出登录时清空旧空间数据；后端则通过 Express 与 Drizzle ORM 连接主 MySQL 8.4 数据库和私有对象存储池。

当外部访客在公开站点发起售前轻量试用、或付款后需要自动开通企业账号时，公开站点后端不直接连接主MySQL 数据库，以免公网入口一旦遭遇异常爬虫冲击就波及核心数据库。跨系统操作统一由公开站点后端携带内部凭据，调用核心业务后端开放的受限内部接口完成。
